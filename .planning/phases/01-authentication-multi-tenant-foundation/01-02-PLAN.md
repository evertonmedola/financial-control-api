  <action>
    Create `src/common/filters/http-exception.filter.ts` implementing `ExceptionFilter` (`@Catch()`, catching everything — both `HttpException` and unexpected errors). For a known `HttpException`, forward its status and message as-is (already sanitized by the throwing code, e.g. `UnauthorizedException('credenciais inválidas')`). For any unexpected/unhandled error, respond `500` with a generic body (e.g. `{"message": "Internal server error"}`) and log the real error server-side via NestJS's `Logger` — never include the stack, error message, file path, or exception class name in the HTTP response body regardless of `NODE_ENV`. Register globally in `src/main.ts` via `app.useGlobalFilters(new HttpExceptionFilter())`. Add a test case to `test/security.e2e-spec.ts` (same dedicated file as Task 1) that forces an unhandled error path (e.g. a temporarily-broken DB call or a route that throws a raw `Error`) and asserts the response body contains neither the literal word "Error" tied to a stack frame pattern nor any `.ts`/`.js` file path.
  </action>

    <automated>npm run test:e2e -- security.e2e-spec.ts -t "error sanitization"</automated>
    <fails_when>the error-sanitization test fails, or the response body for the forced-error case contains a file path or stack-frame-shaped string</fails_when>
  </verify>
  <done>Every error response — expected or unexpected — is sanitized; the real error is only ever visible server-side via `Logger`.</done>
