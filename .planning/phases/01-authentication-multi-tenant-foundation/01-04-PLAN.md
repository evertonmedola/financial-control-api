  <name>Task 1: Global ThrottlerModule + per-route limits on login/register</name>
  <files>package.json, src/app.module.ts, src/auth/auth.controller.ts, test/auth.e2e-spec.ts</files>
  <behavior>
    - A 6th `POST /auth/login` request within 60 seconds from the same client -> 429 (limit: 5/60s).
    - A 4th `POST /auth/register` request within 60 seconds from the same client -> 429 (limit: 3/60s).
    - A request to an unrelated endpoint (e.g. `GET /auth/me`) is governed by the separate global default limit (100/60s), not the tighter login/register limits.
  </behavior>
  <action>
    Install `@nestjs/throttler@^6.5.0`. In `src/app.module.ts`, register `ThrottlerModule.forRoot({ throttlers: [{ ttl: seconds(60), limit: 100 }] })` (import `seconds` from `@nestjs/throttler` — NOT a raw millisecond number, per `01-RESEARCH.md` Pitfall 2's documented v6 ttl-unit trap) as the sane global default, plus `{ provide: APP_GUARD, useClass: ThrottlerGuard }` so every current and future endpoint is covered by default. On `AuthController`, add `@Throttle({ default: { limit: 5, ttl: seconds(60) } })` to `login()` and `@Throttle({ default: { limit: 3, ttl: seconds(60) } })` to `register()` — both endpoints, in the same task/commit, per Pitfall 3's explicit warning against forgetting register.
  </action>
  <verify>
    <automated>npm run test:e2e -- auth.e2e-spec.ts -t "rate limiting"</automated>
    <fails_when>the 6th login attempt within the window does not return 429, the 4th register attempt within the window does not return 429, or either test times out</fails_when>
  </verify>
  <done>Both `/auth/login` and `/auth/register` return 429 after their configured limits; the global default guard covers every other endpoint.</done>
