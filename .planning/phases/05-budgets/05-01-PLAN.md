## Phase Goal

**As a** signed-in user, **I want to** set a standing spending limit per expense category and see how much I've spent and have left for the current month, **so that** I know at a glance whether I'm on track or over budget without doing the math myself.

*(ROADMAP.md's Phase 5 `**Goal:**` line — "Users can set monthly spending limits per category and see exactly how much they've spent and have left" — is a plain capability sentence, not authored in strict "As a/I want to/so that" form via `/gsd mvp-phase`. The "so that" clause above is a direct, non-invented restructuring sourced from 05-CONTEXT.md's `<domain>` Phase Boundary note and BUD-03's explicit "must not silently return just a negative number" requirement — no new facts added, mirroring 04-01-PLAN.md's identical handling of this same situation.)*

## Acceptance Criteria

- [ ] A user can set a monthly spending limit for a category. *(BUD-01, this plan)*
- [ ] A user can view a category's consumed and remaining amounts for the month, correctly excluding transfers. *(BUD-02, this plan)*
- [ ] When spending exceeds the limit, the response explicitly signals an over-budget state. *(BUD-03, this plan)*
