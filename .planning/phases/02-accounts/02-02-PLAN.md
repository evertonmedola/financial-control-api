## Flagged Assumptions (specless-probe, unresolved)

- **ACCT-02 concurrency (unresolved):** concurrent PATCH/DELETE requests targeting the same account are not given a specific ordering guarantee this phase — TypeORM's independent `save()`/`update()` calls apply in whatever order the database processes them (last-write-wins on `name`; a PATCH racing a DELETE is undefined but harmless since no financial data is at stake — `balance` cannot be raced because it has no write endpoint at all this phase). True concurrency-safety work (pessimistic locking) is explicitly deferred to Phase 4, per STATE.md's existing blocker note on TypeORM 1.x locking-API specifics. Not tested this phase; flagged, not silently dropped.
