## Phase Goal

**As a** signed-in user, **I want to** manage my financial accounts (corrente, poupança, carteira, cartão de crédito) with an initial balance, **so that** their balances accurately reflect my transaction history over time.

## Acceptance Criteria

- [ ] A user can create an account of any supported type (corrente, poupança, carteira, cartão de crédito) with an initial balance.
- [ ] A user can list, view, update, and delete only their own accounts — never another user's.
- [ ] A credit card account's balance represents amount owed (a liability), not amount held.
- [ ] An account's balance never drifts from what was set at creation (this phase's scope of the "no drift" guarantee — full transaction-derived reconciliation is Phase 4).

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| client → POST /accounts | untrusted request body crosses here; JWT proves identity but every field (type, balance, name, and any extra field) is untrusted input |
