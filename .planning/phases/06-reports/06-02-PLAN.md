    Edit `src/reports/reports.service.ts`: add two private helpers. `getMonthBounds(month: string): {start: string; end: string}` parses `month` (`"YYYY-MM"`) into `year`/`monthIndex` (0-based), then computes `start` as `${year}-${pad(monthIndex+1)}-01` and `end` as that month's real last day via `new Date(Date.UTC(year, monthIndex+1, 0)).getUTCDate()`, zero-padded — mirrors `BudgetsService.getCurrentMonthBounds`'s UTC-date-parts computation exactly, but parameterized by the requested `month` string instead of `new Date()`. `getPreviousMonthBounds(month: string): {start: string; end: string}` computes the immediately preceding calendar month from the same `month` string — build `new Date(Date.UTC(year, monthIndex - 1, 1))` (JavaScript's `Date` correctly rolls a `monthIndex` of `-1` back into December of the prior year, so no manual January-boundary branch is needed) then derive its own `"YYYY-MM"` string from `getUTCFullYear()`/`getUTCMonth()` and delegate to `getMonthBounds`.

Build the UNION of categoryIds from `currentSpend.keys()` and `previousSpend.keys()` (a `Set`) — deliberately the union, not just the current month's keys: a category with real spend last month and none this month is a meaningful "dropped to zero" delta a user would want to see, mirroring Budgets' Pitfall-4 "never null/undefined/NaN for a zero-transaction category" convention applied to whichever side of the comparison is missing.
